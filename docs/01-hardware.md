| 部件 | 规格 | 数量 | 备注 |
|---|---|---|---|
| 机械臂结构件 | SO-100（主从，leader + follower） | 1 套 | 3D 打印件 + 标准件 |

## 2. 端口与设备

| 用途 | 端口/索引 | 说明 |
|---|---|---|
| leader（示教臂） | `COM5` | 只读取角度，评估时不上力矩 |
| follower（执行臂） | `COM6` | 策略驱动这一条 |
| 侧视相机 | `camera_index: 0` | 能看到机械臂本体、纸盒、积木 |
| 俯视相机 | `camera_index: 2` | 能看进纸盒内部 |

> **两个坑**
> 1. COM 号按 USB 物理口分配。插到别的口会变号，评估时报 `Failed to open port 'com5'`。
> 2. **相机 index 会在重启/插拔后漂移**。跑之前务必用 `scripts/probe_cameras.py` 生成 `cam_<i>.jpg`
>    核对视角；`laptop` 与 `phone` 互换**不会报错**，只会让策略看得错位、抓得很差。

## 3. 舵机寄存器（STS3215，SCS 协议）

| 功能 | 地址 | 字节 | 说明 |
|---|---|---|---|
| Torque_Enable | 40 | 1 | 0 断电可手掰，1 锁死 |
| Goal_Position | 42 | 2 | 目标位置 0–4095 |
| Present_Position | 56 | 2 | 当前位置 |
| Present_Speed | 58 | 2 | 当前速度 |

角度与位置映射：`pos = (angle + 90) / 180 × (3072 − 1024) + 1024`（−90°…+90° ↔ 1024…3072）。
`src/mcp_server.py` 里手写的包格式（`FF FF ID LEN INST PARAMS CHK`，校验和 `~(sum) & 0xFF`）就来自这套协议。

## 4. 标定

`.cache/calibration/so100/main_{leader,follower}.json` 目前是**初始占位值**：

```json
{"homing_offset": [2048,2048,2048,2048,2048,2048],
 "drive_mode":    [1,1,1,1,1,1],
 "start_pos":     [2048,...], "end_pos": [1024,...]}
```

含义：采集数据与推理**都用这一套**，所以两端自洽、动作可以镜像；但它没有物理零点，
不同机器之间不可复用。**一旦重新标定，必须重新采集数据**，否则同一组动作数值对应的物理姿态会变。

真正的标定流程（零点 / 方向 / 量程 / 重复定位精度）尚未实现，是下一步工作，见 README 的局限章节。
