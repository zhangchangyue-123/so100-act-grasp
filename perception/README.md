# 感知层：颜色检测与积木跟踪

三个脚本是早期（接入模仿学习之前）用来做视觉定位的实验，仍然有参考价值：
可以在**不训练模型**的前提下，快速验证相机、光照、颜色阈值是否合适。

| 脚本 | 做什么 | 输出 |
|---|---|---|
| `color_block_detect.py` | 蓝色 / 黄色双阈值掩码，最朴素的可视化 | 3 个窗口：原图、蓝色提取、黄色提取 |
| `blue_block_detect.py` | 鼠标框选参考积木 → 像素/厘米标定 → 测积木的宽高与质心 | 轮廓 + 尺寸标注 + 掩码窗口 |
| `blue_block_track.py` | 取最大色块质心，绘制最近 100 帧轨迹 | 轨迹线 + 起点/终点标记 |

## 运行

```bash
# 相机索引各机器不同，用环境变量指定（默认 1）
$env:CAMERA_INDEX = "2"
python perception/blue_block_detect.py
```

`blue_block_detect.py` 需要一个参考图来标定“像素/厘米”，默认读同目录的
`blue_block_capture.jpg`（可用 `$env:REF_BLOCK_IMAGE` 指定别的图）。

按键：`q`/`ESC` 退出，`s` 保存当前帧，`c` 清轨迹（`blue_block_track.py`），`r` 重新标定。

## 为什么没有用它做“自动判定成功”

这正是 [../docs/05-lessons.md](../docs/05-lessons.md) 记录的三次失败尝试的来源：

1. 场景里有**红色线束**，与红色积木同色系 → 质心满屏乱跳，面积出现 12× / 32× 的异常；
2. 积木靠近镜头时变成大面积斜四边形 → 形状约束（圆度、长宽比）反而把它过滤掉；
3. 俯视相机装在机械臂上，**随臂移动**，任何“固定桌面 ROI”的假设都不成立。

结论：颜色阈值法适合**快速验证与调试**，不适合做指标统计。要做可靠的自动评测，
应该是「固定外置相机 + 目标检测/分割模型 + 固定 ROI」，这也正是下一步计划。

> 训练 YOLO 检测器所需的标注与配置在早期工作里已经有一份（父目录的 `yolo/`、`my_custom_data.yaml`、
> `convert_labels.py`、`weights/`），可以直接接上来做“积木是否在盒内”的自动判据。
